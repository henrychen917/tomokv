v7 (forked from frozen v6) adds **cross-shard MGET** via scatter-gather, gated by `thredis-opt-cross-shard` (MODIFIABLE bool, **default OFF**). Single-key commands still go to one owning shard; before v7 a multi-key MGET ran inline on the IO thread's empty `server.db` → all-nil (silently wrong), so MGET was unsupported.

**Design (as built):** at dispatch, split the MGET into one single-key **sub-fake per key** (`createFakeClient`), each dispatched to its key's shard via the same `workerIndexForKey`. Each sub **serializes its MGET element into its own reply buffer ON the owning worker** (`addReplyBulk` → correct INT-encoding, synchronous copy, no cross-thread refcount — chose this over zero-copy value forwarding, which would crash on INT-encoded values and reopen a use-after-mutate window). Last sub to finish (`fetch_sub(pending, ACQ_REL)` chain) sets the group-head ring-slot's reply bit (into the head's captured CDB 0); the IO drain reassembles `*N` + spliced sub buffers in key order onto the real client. Three hooks in server.c: dispatch split, worker-loop sub exec+completion, drain reassembly. Full writeup: `THredis-opt-v7/CROSS_SHARD_IMPLEMENTATION.md`.

**Bugs caught pre-build (via -fsyntax-only + inspection):** csCmdType↔enum name clash; workerPauseCpu use-before-decl; `sdslen(v->ptr)` crash on INT-encoded values; fan-out **deadlock** under opt_batch_push (fixed: csPushSpin publishes tail immediately + spins); sub-fake `conn==NULL` → `_prepareClientToWrite` silently drops the element (fixed: borrow head->conn + set CLIENT_WORKER_PENDING; reassemble onto real, not head).

**Validation-caught hang (the big one):** an isolated cross-shard MGET hung ~35% of the time. Root cause: the IO event loop `aeProcessEventsIO` (ae.c) sets its epoll_wait timeout SOLELY from the per-thread `replyWorking` counter — `replyWorking==0` ⇒ blocks forever, `>0` ⇒ 100us poll. The single-key path does `replyWorking++` at dispatch / `--` at drain; cross-shard dispatch left it untouched, so after pushing MGET subs the IO thread slept and never drained the completed group (the head carries no socket event). It "worked" under rapid-fire because the next command's socket event woke epoll and drained it as a side effect. FIX: `replyWorking++` in the cross-shard dispatch branch; `replyWorking--` in all drain paths for the csgroup head (capture `was_cs` before csReassemble NULLs csgroup). Lesson: any worker-completed reply with no socket event of its own MUST bump replyWorking or the IO loop won't wake.

**Separately discovered:** FLUSHALL/FLUSHDB **hang** on the sharded build (v6 AND v7 — pre-existing), and DBSIZE/OBJECT return wrong values — keyspace-wide & non-whitelisted commands aren't wired to the worker shards. So benchmarks must reset via server RESTART, not flushall. Orthogonal to cross-shard.

**Full command set (2026-06-20, all validated):** MGET, MSET, DEL, UNLINK, EXISTS, TOUCH (scatter-gather via csGroup), + FLUSHALL/FLUSHDB (queue-ordered flush sentinels, fire-and-forget OK reply). Reassembly by ctype: MGET splices per-sub element buffers in key order; MSET replies +OK after barrier; DEL/EXISTS/TOUCH/UNLINK sum per-sub integer into g->rcount. Gating: MGET argc>=2, MSET argc>=3 odd, DEL argc>=3 (single-key stays on whitelist), UNLINK/EXISTS/TOUCH argc>=2 (not whitelisted → need cross-shard even single-key). **MSET value gotcha:** give the sub a PRIVATE dupStringObject copy (refcount 1) so setKey can consume it like stock; then mirror msetGenericCommand EXACTLY — setKey + incrRefCount(argv[2]) ("refcnt not incr by setKey()"), else csFreeSub frees the in-dict kvobj → UAF. User's design principle (confirmed): fully async — IO never blocks (does other work, polls via replyWorking), workers never wait on each other, last sub signals, IO reconstructs; reconstruct-on-IO is correct (worker-side reconstruction would force a worker to wait + touch other shards). FLUSHALL must be queue-ordered (FIFO), NOT prioritized. Validated: functional + ASAN clean (200 mixed rounds, 0 leak/UAF), MGET oracle 23.2M positions 0-corrupt. Validation gate: `thredis-mkey-oracle-v7` (SET-populate, positional MGET check) = 0 corruptions + ASAN clean under churn/toggle-storm → ship default-off; else back out. STATUS (2026-06-20): **VALIDATED, SHIPS default-off.** Native+ASAN clean: oracle 0-corrupt (23.2M positions native / 6.3M ASAN), toggle-storm survived, wide-256-key backpressure clean, ASAN no leaks/UAF, 0/80 hangs post-fix. Report: THredis-opt-v7/CROSS_SHARD_IMPLEMENTATION.md. Next: fix FLUSHALL (user asked), then wide 6h sweep. See [[thredis-benchmarking-methodology]] for the planned v7 sweep.
