### Implementation

- O1 (`e7b1f762c`): `multi_retries_` has a counted fast prefix. Each service call reserves the starting rotation head, polls every starting fast fragment once, then polls that rotation head once. Retries/promotions append behind unpolled fast members. Existing empty-queue tests are unchanged. Placed/ARRIVE/barrier/decision waits and promoted next waiters use `RetrySoon`; other refused placements keep the rotation. Placement and retirement select the oldest live waiter on each affected key. The existing owner-local `execution_noted` byte supplies a spare promotion bit, which travels with the fragment when its shard forwards. Synchronous promotion moves a queued EXEC fragment without allocation; retirement outside a multi task leaves the hint for its rotation turn. Scatter units keep their existing deferred queue.
- O2 (`6c70b47f4`): EXEC and scatter units retain an owner-local older blocker, pinned by its existing `watch_refs`. Only a full refused scan that saw no younger placing claim may cache a holder. A live cached holder skips the next full scan; decision/cancellation releases the pin and resumes scanning. An immediate temporary pin protects a selected holder against retirement during later key scans. Writers have no new cache, field, allocation or predicate.
- Information arm (`8adf2b69d`): `TOMO_EXECFAIR_WRITERS_FIRST` reverses only the adjacent deferred-writer/multi-retry calls at all eight existing pass sites, including generated reorder envelopes. The default order remains unit-before-writer. POST-ALT is for comparison; delete the switch after measurement unless the owner explicitly keeps it.
- Proof commits recognize `RetrySoon` in direct fixtures, expand existing txnorder2 rows to atomic 0/1, and add one fast-poll witness row. The strict R7 FIFO inventory adds exactly three EXEC promotion callbacks per runtime, with an additional missing-callback negative control; all 311 ordinary bodies match the current candidate's FIFO twin. This is a separate check from the PRE/POST differences below. The forced atomic-0 fixture paths represent EXEC children; ordinary atomic-0 admission remains unchanged.

No version comparison, placement wait predicate, wound decision, writer episode rule, reader path or per-operation layout lock changes. O1 changes scheduling; O2 skips scans whose refusal is still forced by a pinned older holder. `atomic_txn_fast_polls` and `atomic_txn_poll_skips` are updated on unit paths only. A skipped cached refusal bypasses the old full-scan `atomic_txn_place_waits` increment; compare `place_waits + poll_skips` when counting refused placement polls across arms. Do not treat a fall in `place_waits` alone as fewer waits.
