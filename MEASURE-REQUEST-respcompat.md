## Result and remaining owner work

NET13's listed framing errors, NET14's empty arrays, NET15's LF termination, and
NET16's count grammar are implemented. NET19 is **skipped under its zero-byte
condition**: the direct `reply_line_text` substitution grows the existing TYPE
handler from **433 to 801 bytes** in the production string TU. The experiment
also changes five other bodies; it is retained only in `build/respcompat/NET19`.

The ordinary parser is **not byte-identical**. Canonical length validation needs
an additional check; cold count completion/revalidation changes its continuation
and register allocation. The existing fixed compiler budgets also select some
different inlining decisions elsewhere. The body audit below inventories these
changes rather than claiming a hot-path no-op. **The maintainer's 14-cell null and
live compatibility/gate verdict are pending.** No throughput or cycles/op claim
is made from static instruction totals.

Successful decoding of quoted/escaped inline arguments remains PRE behavior and
is a separate compatibility gap. This ERROR-path lane validates quote balance
and quote closing grammar without rewriting pinned receive bytes or using reply
storage for argv. Full decoding requires argv-owned storage outside this file's
current ownership interface. Existing pre-AUTH policy/error selection is also
unchanged; the table below describes the authenticated request parser (including
the configured bulk-limit path), not Redis's additional unauthenticated errors.
