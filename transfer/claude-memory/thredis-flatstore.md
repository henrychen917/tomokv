FLATSTORE = one per-(node,db) lock-free open-addressing table replacing the 16384 per-bucket dicts of a shared node kvstore (kills the ~4.5% p32 random-lookup locality tax: one warm table header vs one of 16384 scattered dict structs). Chosen over GROUP-DICT because the user finds the table more hardware-arch-inspired ([[thredis-shared-kv-never-built]] is the shared-kv build-out this lives on). On branch `2s-numa-shared-kv-dev` in worktree `$J/stable-w` ($J=/shared/Projects/.claude/jobs/fd085c8e/tmp).

**Layout** (src/flatstore.{h,c}): `flatSlot{_Atomic uint64_t ctrl; _Atomic(dictEntry*) kv}` 16B (4/line). ctrl = [63:16] 48-bit hashtag | [15:2] 14-bit bucket | [1] TOMB | [0] OCCUPIED; 0=EMPTY. Bucket = xxh64&16383 is a per-SLOT tag (reshard stays O(1): flip ex_bucket_table, zero table work). Single-writer-per-KEY (one owner per bucket) ⇒ CAS only resolves cross-KEY physical collisions. GET lock-free (acquire probe), INSERT CAS, DELETE tombstone. Gated `--thredis-flat-store 1` + shared_node_dbs (wpn>1); knob is IMMUTABLE. Note ctrl stores tag+bucket but NOT h[15:14], so a home slot can't be reconstructed from ctrl for tables >16384 slots.

FIX D = loop_seq bumped release EVERY exSlice pass (was migration-only). In-place mutation DISABLED under flat (dbSetValue forces copy + retires old) to close overwrite UAF. Closed the cross-shard-reader UAF windows.

**Stage 2 online resize** (done, commit b1132b7ea): initial table 256K slots/4MB (was 128MB pre-alloc). flatInsert flags resize_needed at 0.6 (used+tombs)/size. Coordinator flatResizeCoordinate (beforeSleep, main thread): arm exclusive via mig_arm_lock (refuse if migration_active/tomo_flush_gate), set flat_resize_active=1, spin until every live worker sets resize_parked=1 at the exSlice-top park gate, flatTableGrow each flagged table (alloc 2x, copy LIVE slots recomputing each key's hash via tomoKeyHash since ctrl lacks h[15:14]), kvstoreFlatSwap (plain kvs->flat=nw), flatTableFree(old) frees slots + drains old's retire garbage IMMEDIATELY, clear flat_resize_active. Safe-to-free invariant: worker parks at exSlice TOP after bumping loop_seq + finishing prior batch ⇒ no in-flight read pointer held. FIX C = reshardArm refuses while flat_resize_active. The park gate is the ONLY quiescence needed because prefetch bails under flat (kvstoreGetDict→NULL) so the worker exec path is the sole hot flat access. Sanity-gate caught an uninitialized resize_needed (zmalloc not zcalloc) that spuriously grew 16 empty dbs.

**Stage-2 review fixes** (commit 9bba8cb82, after adversarial workflow found 5 confirmed): the park predicate `tmWorkerLive` was INCOMPLETE — a worker flipped EX→IO (or mid EX→PARKED via balancer) has liveness=false but still runs exSlice to drain KEYS/MGET-borrow straggler subs, so the coordinator skipped it and freed the table mid-read (CRITICAL+MEDIUM UAF); and `resize_parked` had no generation so a preempted worker's stale ack satisfied the next resize (HIGH UAF). ROOT FIX: replaced resize_parked with a per-worker `in_flat_section` flag set at exSlice top (after the gate) + cleared at its single return; coordinator drains ALL allocated workers' flags to 0 — identity-complete (any mode) + stale-free (cleared every batch). seq_cst announce-then-check (worker) pairs with seq_cst set-active-then-scan (coordinator) closing the TOCTOU. Also: flatTableGrow picks target by LIVE load not (used+tombs) so tomb churn rebuilds SAME-SIZE not unbounded-double (#8 memory); grow ONE table/beforeSleep pass (#4 STW); trigger 0.6→0.5 (#3 headroom).

**8B single-word slots DONE** (commit d3511dfd6, user chose "A now, arena-B later"): 16B slot (8B ctrl + 8B kv ptr) → ONE 8B word: 15-bit tag [63:49] + TOMB [48] + masked kv ptr [47:0] (x86-64 canonical 48-bit ptr fits losslessly). Table HALVES: sizeof(flatSlot) 16→8, ~32→~16 B/key. Protocol SIMPLER: INSERT=1 CAS (tag|ptr atomic, no ctrl/kv window), DELETE=1 store (FIX-A two-step gone). 14-bit bucket no longer stored — recomputed from key in rare range scans. THE GOTCHA (crash it caused + fixed): a flat "link" is &slot->w; generic code does dictGetKV(*link) which would deref the tag-tainted word → non-canonical ptr crash. FIX: decodeMaskedPtr (dict.c) now also masks high 16 bits [63:48] — provable no-op for real dict entries (canonical ptrs, high bits 0), strips the flat tag; fixes all 7 db.c link-deref sites at once. flatInsert asserts ptr fits 48 bits. Memory measured (distinct values, 1 db): 200k keys OLD 27.9→NEW 21.9 MB (table delta); 1M distinct NEW=70.5 MB. Validated: functional + full ASAN storm (254 flips×3 resizes+MGET/KEYS+delete, exact dbsize, distinct readback) clean.

**8B review + fix DONE** (commit 9ea31e7fe): adversarial review (5 dims) found ONE critical root bug — the 8B merge reintroduced the FIX-A hazard. Async-delete (lazyfree) did SetAtLink(NULL)-preclear then flatDelete; 16B left ctrl=OCCUPIED (unclaimable) in the window, but 8B has no "occupied-no-ptr" state so preclear stored FLAT_TOMB (REUSABLE) → concurrent cross-key insert claims the slot → flatDelete clobbers it → key loss + QSBR-UAF of the reinserted value + tombs underflow. FIX: for flat, dbGenericDelete skips the async preclear path (`if (async && !kvstoreIsFlat)`) — routes EVERY delete through the single-store flatDelete in TwoPhaseUnlinkFree (one atomic LIVE→TOMB, no window) + flatRetire (QSBR). Also fixes latent freeObjAsync-not-QSBR-safe. Preclear branch in kvstore.c now assert(0). Validated ASAN + lazyfree + overlapping UNLINK/reinsert churn: exact dbsize, no loss/UAF/leak. Throughput A/B: 8B is a WASH vs 16B (SET ~1.3M, GET ~1.45M, within noise) — memory halved for free. GET/SET-priority-safe.

**GENERAL LESSON**: the 8B single-word slot removed the "occupied-but-no-value" state the 16B ctrl provided — any 2-step delete/mutation that relied on an unclaimable intermediate must become single-atomic-store under 8B.
