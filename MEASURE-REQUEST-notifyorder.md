### Changes and boundaries

`notify_flat_emit` attributes only the by-name sink's Expired events to the command batch. `notify_flat_store_emit` enters the old unattributed body directly only for the known production callback; opaque custom callbacks remain intact. Active expiry, field reaping, eviction, walkers, RANDOMKEY, blocking carriers, batch capacity and allocation fallbacks retain the keyless route. Expired priority is 0 and New is 1; the existing argument/child/call bands remain.

Physical records survive both abort branches in `notify_take_batch` and all five script discard/retry sites. Compaction allocates nothing and does not move owned key strings. Destructors retain their original teardown behavior. The allocation fallback observes SAVE once, does not count a premature drop and uses the existing keyless producer. Heap sizes remain `NotifyRecordImpl=32`, `NotifyBatch=416` bytes in both PRE and POST; the physical fields occupy existing padding. All locked production layouts build unchanged.

The directed SET case exposed an additional omission: the armed raw overwrite probe can expire a key through `find_without_touch` before `insert_notify` observes it. The armed string helper snapshots the owner-local physical-expiry counter and observes its delta only after the original probe returns `NotPossible`. Every such exit precedes memory admission, so only its named lookup can advance the counter; Updated/OOM are excluded because admission can expire unrelated keys. Read-local's probe remains an unconditional no-op. No extra lookup, policy touch, write, or probe eligibility change is introduced. The deterministic serverless fixtures assert exactly one physical Expired with an unrelated live atomic version in both read-local states and exactly one LFU increment for one full SET. The first extra-lookup implementation failed these checks, including the full-command LFU regression (`QFaGzm`); it was replaced, not excused. Clean string handlers do not execute the observer. `flatstore.h` is unchanged.

The full production-unit sweep caught an opaque callback contract regression in the first sink split: `notify_flat_store_emit` bypassed a custom sink's callback and interpreted its context as a Shard. The unchanged flushfix expiry assertion rejected it (`cB97sf`, after 513 other rows passed). Both `flushfix_unit.cc` and `rehash_waits_unit.cc` register opaque custom contexts. The corrected entry routes only the known production callback to the unattributed Shard body; every custom observer keeps its original callback. Those assertions remain untouched. The interrupted run and exact failing binary are retained, and fresh PRE binaries of both units reuse the frozen baseline production objects.

A5 was reproduced before its fix in atomic 0/1 × 1s/2s × epoll/uring. PRE writes two ordinary PUT records and reloads both values, but loses the script's group boundary. Redis 7.4.10 writes MULTI, SET, SET, EXEC. POST routes the existing persistence fallback's ScriptRoute branch through `xshard_aof_emit_local`, producing two GPUT records with one nonzero ticket and a matching GCMT, with no ordinary PUT/DEL for those keys; live and reloaded values match the oracle. `Op`, IO retirement and executor routing remain byte-for-byte source-identical to PRE. The fix does not claim PRE loses both values on an intact reload; its observed defect is ungrouped persistence and the resulting partial-recovery exposure.

Optional R2, S9, A1 and A2 are deferred. Res-1's program-order rewrite is not attempted. No new thread, queue, ring, wake, per-operation retry, seqlock or independently shared publication line is introduced. The added stores are confined to the existing heap batch and its already-written counter line under its existing mutex.

### Directed proof and corrections to the proposed battery

The tests run through the gate's own `notify_order`, `notify_aof` and `netcmd_units` interfaces. The notification row has 12 complete legs: atomic 0/1 × epoll/uring × (1s read-local 1, 1s read-local 0, 2s read-local 0). The AOF row has 8 legs: atomic 0/1 × epoll/uring × (1s read-local 1, 2s read-local 0). Both own a Redis 7.4.10 oracle on PORT+1. Missing oracles fail the row.

The battery checks exact ordered keyspace/keyevent frame lists against explicit expectations and the oracle, never sorts, and runs C1×8, C2×2, C3×4, C4×4, C5–C8 plus NOLOOP. C2 has eight expired keys across at least two owners and three shards, with four expiries sharing the publisher's actual coordinator; PRE's contiguous keymiss chain cannot interleave those expiries. The publisher IO is witnessed through accepted-client deltas. Load balancing and flip are disabled. Each arm uses fresh keys, proves the key live, waits past the server's deadline, proves flat counters/no frames before access, and checks exact replies, counter deltas, subscriber barriers and absence of extra frames. NOLOOP requires an invalidation on a second client while forbidding it on the expiring client.

Three design preconditions needed correction, without relaxing event expectations:

* `atomic_entries` is cumulative. The live quiescence witness is `atomic_pending_entries`, alongside `atomic_inflight` and `pubsub_inflight`.
* TomoKV's CONFIG normalization of `AKEmn` drops `n` when it reparses the normalized `A` form. The battery spells the observed classes explicitly as `g$lhxKEmn`. This separate configuration discrepancy is flagged below.
* Atomic MSETNX can abort on the live-key owner before the expired-key fragment begins. C7 re-arms at most eight times on fresh state only when reply/counters/frames prove zero physical effects. Any physical deletion with a missing or misordered event fails immediately. Its fired counter includes the one speculative New record later discarded in atomic mode; exact delivered frames still contain only Expired. PRE and POST both satisfy this C7 physical-effect witness. This early cancellation is part of the existing A6 scheduling discrepancy, not fixed here.
