# `migPushFenceIfNeeded` / `drain_ack` / `fence_acked` — migration cutover execution-drain fence

## What it is

The migration drain fence is a per-IO-producer sentinel protocol intended to exclude old-owner execution from an ownership cutover. When a migration enters `MIG_DRAINING`, each live IO producer's before-sleep or range-hold path calls `migPushFenceIfNeeded`; observing a fresh `fence_gen` makes that producer insert one marker into its FIFO queue to the source worker. The source worker acknowledges that producer when it reaches the marker in the execution loop; the coordinator wakes unresolved live slots and either waits for their markers, aborts on its configured timeout, or uses the retired-tail fallback for a non-live producer before flipping the bucket table. (`src/server.c`) The coded ordering has a stage-only-scratch hole described under [Coded temporal-exclusion limit](#coded-temporal-exclusion-limit); the source does not unconditionally enforce the intended exclusion when that scratch is nonempty. (`src/server.c`)

The sentinel rides the same [`exQueue` staged SPSC ring](ring-push-pop.md) as ordinary IO-to-worker jobs. Its position supplies FIFO ordering for work already in that ring: work published by the IO slot before the sentinel is ahead of it, and dispatch paths that encounter the `MIG_DRAINING` holds wait before routing new in-range work. (`src/server.c`) A fake retained in the IO thread's separate stage-only scratch is not yet in the SPSC ring and is not covered by that FIFO statement. (`src/server.c`)

### Parked-client storage

`redisServer.clients_mig_parked` is `list *[TOMO_IO_THREADS_MAX + 1]`, a fixed 129-pointer array: its exact source footprint is `129 * sizeof(list *)`, or 1,032 bytes on LP64. The array has no explicit cache-line alignment or padding. ([src/server.h:1486](../../../src/server.h#L1486), [src/server.h:3203-3210](../../../src/server.h#L3203-L3210)) Initialization allocates one empty list header for every index `0 .. io_threads + tm_ngrow_io` inclusive. A `list` contains five pointers and one `unsigned long`, so each header is `sizeof(list)` and normally 48 bytes on LP64; at the compile-time maximum, 129 initialized headers request 6,192 bytes in addition to the pointer array. ([src/server.c:5982-5995](../../../src/server.c#L5982-L5995), [src/adlist.h:27-34](../../../src/adlist.h#L27-L34), [src/adlist.c:22-33](../../../src/adlist.c#L22-L33))

Each parked client adds one allocated `listNode` containing `prev`, `next`, and `value`, so its exact source footprint is `sizeof(listNode)` and normally 24 bytes on LP64. `listAddNodeTail` allocates that node; `listDelNode` unlinks and frees it. Neither list allocation path asks for cache-line alignment or isolation. ([src/adlist.h:16-20](../../../src/adlist.h#L16-L20), [src/adlist.c:102-132](../../../src/adlist.c#L102-L132), [src/adlist.c:169-177](../../../src/adlist.c#L169-L177)) The full client's existing execution tail embeds plain `listNode *mig_parked_node` and plain `int mig_parked_tid`; fake reset and real-client construction initialize both to null/zero. The list and embedded membership fields are not atomic. Parking, release, and unlink operate on the list indexed by the current or saved IO identity; the client-thread migration predicate refuses any client with a non-null `mig_parked_node`, keeping list ownership on the same IO thread. ## Producer and consumer roles

- The producer set is slot `0` for the main event loop, base IO slots, and growth IO slots. The coordinator computes its exact scan bound as `nprod = server.io_threads + server.tm_ngrow_io` and iterates `t = 0 .. nprod - 1`. ([src/server.c:15854-15864](../../../src/server.c#L15854-L15864), [src/server.c:15990-16010](../../../src/server.c#L15990-L16010))
- For a live slot, the thread currently owning that IO identity is the sole sentinel producer for its `source_worker.queues[iotid]` lane; its TLS `mig_local_fence_gen` suppresses a second marker for the same `fence_gen`. ([src/server.c:15630-15642](../../../src/server.c#L15630-L15642))
- The source worker is the queue consumer and the normal acknowledgement writer. It derives the acknowledgement index from the queue lane `i`, not from the pointer value stored in `drain_ack`. ([src/server.c:22096-22105](../../../src/server.c#L22096-L22105))
- The coordinator reads acknowledgements and is also the acknowledgement writer for a non-live producer slot whose queue has completely retired. ([src/server.c:15985-16010](../../../src/server.c#L15985-L16010))

`migProducerLive(t)` treats slot 0 as live, otherwise consults the slot's poly-thread context and acquire-loads `ctx->mode`; without a poly context it treats base slots `t < server.io_threads` as live. ([src/server.c:15820-15840](../../../src/server.c#L15820-L15840)) A live nonzero slot is woken through `tomoAtomicWakeProducer`; slot 0 is not woken because it is the thread running the coordinator. ([src/server.c:15842-15852](../../../src/server.c#L15842-L15852))

## Protocol as coded

### 1. Raise and publish a new fence

A successful `reshardArm` precedes the fence: while holding `mig_arm_lock`, it plain-stores `lo`, `hi`, `src`, and `dst`; release-stores `MIG_COPYING`; release-increments `migration.gen`; release-increments `mig_arm_seq`; and release-stores `migration_active = 1` last before releasing the arm lock. `reshardBeginCutover` acquire-loads the active byte and then acquire-loads `phase`, so a coordinator admitted through that channel observes the arm fields and `MIG_COPYING`. ([src/server.c:15584-15621](../../../src/server.c#L15584-L15621), [src/server.c:16149-16166](../../../src/server.c#L16149-L16166))

Before opening the producer fence, the coordinator has already sequence-consistently closed `tomo_atomic_cutover_gate`. In `CO_WAIT_ATOMIC` it sequence-consistently folds every admission-census slot; only when the sum is zero does it compute `tomoAtomicLifecycleRangeRefs(src, lo, hi)`, and it remains in the pre-drain while either the unsealed sum or the range-reference count is nonzero. A reservation ordered after the close must observe the closed gate and roll its own slot back, while a reservation admitted before the close remains in its fixed slot until sealing. The timeout/abort path leaves ownership unchanged and never publishes `MIG_DRAINING`.

After both counts reach zero, it accounts and clears any atomic-fence wait interval, resets `fence_acked[t]` to `0` with relaxed stores for every `t < nprod`, relaxed-increments both `fence_gen` and `migration.gen`, and release-stores `MIG_DRAINING` to `migration.phase`. It then resets its fence timers and release-stores `CO_DRAINING` to `co_state`. ([src/server.c:15929-15950](../../../src/server.c#L15929-L15950))

The branch order is load-bearing: the acknowledgement reset and new generation are sequenced before the `phase` release, so a producer that acquire-observes `MIG_DRAINING` is ordered after the new fence state. ([src/server.c:15936-15945](../../../src/server.c#L15936-L15945))

### 2. Insert exactly one sentinel per live producer

`migPushFenceIfNeeded` performs these branches in order:

1. Acquire-load `migration.phase`; return unless it equals `MIG_DRAINING`. ([src/server.c:15634-15635](../../../src/server.c#L15634-L15635))
2. Acquire-load `fence_gen`; return when the value is zero or equals this thread's `mig_local_fence_gen`. ([src/server.c:15636-15637](../../../src/server.c#L15636-L15637))
3. Allocate a fake using `mig_fence_parent`, then set `clientTail(sentinel)->drain_ack` to `&server.migration.fence_acked[0]`. The pointer is only a non-`NULL` type marker; the consumer chooses the actual cell by queue index. ([src/server.c:15631-15640](../../../src/server.c#L15631-L15640), [src/server.c:22096-22102](../../../src/server.c#L22096-L22102))
4. Call `csPushSpin(server.migration.src, sentinel)`, which stages into the source worker's lane for the current `iotid`, retries on full, and finishes with a release-store of `q->tail` followed by the lane advertisement. ([src/server.c:15638-15641](../../../src/server.c#L15638-L15641), [src/server.c:12544-12586](../../../src/server.c#L12544-L12586))
5. Only after `csPushSpin` returns, copy `fence_gen` into the TLS `mig_local_fence_gen`. ([src/server.c:15640-15641](../../../src/server.c#L15640-L15641))

The complete direct caller set is `beforeSleepIO` for non-main IO threads, `beforeSleep` for producer slot 0, `migHoldClientIfDraining` before it parks a client, and the synchronous `migHoldKeyIfDraining` wait loop. The two before-sleep callers first test `migration_active` with a relaxed load; both hold helpers have already acquire-observed `MIG_DRAINING` before calling the push helper. ([src/server.c:4387-4395](../../../src/server.c#L4387-L4395), [src/server.c:4438-4448](../../../src/server.c#L4438-L4448), [src/server.c:15696-15711](../../../src/server.c#L15696-L15711), [src/server.c:15749-15769](../../../src/server.c#L15749-L15769))

`drain_ack` also appears in `exDispatchPush`'s stage-only admission predicate: a full fake whose `drain_ack` is non-`NULL` is excluded from the TLS scratch and takes the direct path after any existing scratch is drained. The migration sentinel itself is sent through `csPushSpin`, so it does not enter `exDispatchPush`; the predicate is nevertheless the other coded use of the named marker field. (`src/server.c`)

### 3. Exclude new range work

Before taking a client fake-ring slot, `processCommand` calls `migHoldClientIfDraining` whenever the relaxed `migration_active` gate is nonzero. The exact key predicate is `b = (int)(xxh64(key, len) & TOMO_BUCKET_MASK)`, followed by `b >= migration.lo && b < migration.hi`. The hold acquire-checks that `phase == MIG_DRAINING`, then uses `migAnyKeyInRange`: if the command's legacy range key spec starts at argument 1 and argument 1 exists, the helper tests **only** `argv[1]` and returns that result; otherwise it calls `getKeysFromCommand` and tests each returned SDS-encoded key until the first hit. ### Coded temporal-exclusion limit

`exDispatchPush` can retain an admitted ordinary fake in thread-local `tomo_stage` without putting it in any `exQueue`: under the stage-only admission conditions it writes the fake and destination worker into the scratch and returns. The scratch reaches the rings only when `tomoReorderDrain` later calls `exDispatchDirect` in arrival order. (`src/server.c`)

None of the four `migPushFenceIfNeeded` call paths first drains `tomo_stage`. Both before-sleep paths push before `handleWorkerReplies`, whose leading `flushExQueues` later drains the scratch. The client-hold path pushes and marks the client stalled; `processInputBuffer` then breaks its parse loop and reaches the parse-end `flushExQueues`. The synchronous key-hold path can retain the scratch throughout its phase-wait loop. The sentinel bypasses stage-only admission through `csPushSpin` and is immediately tail-published. Consequently, if the TLS scratch is already nonempty, the sentinel can enter and be published in the source ring first, and the previously admitted scratch fake can be appended behind it—or, for the synchronous hold, remain outside the ring until after the phase changes. (`src/server.c`, `src/networking.c`)

The source worker release-acknowledges as soon as it executes the earlier sentinel, while the scratch fake behind it has not yet executed. The coordinator can therefore accept that producer's acknowledgement and reach the flip without this later ring entry retiring. There is no scratch-empty check or pre-sentinel `tomoReorderDrain` in `migPushFenceIfNeeded`; the implementation does not enforce complete temporal exclusion in this state. ([src/server.c:15634-15642](../../../src/server.c#L15634-L15642), [src/server.c:15985-16010](../../../src/server.c#L15985-L16010), [src/server.c:22096-22105](../../../src/server.c#L22096-L22105))

The outer `migration_active` checks on the command and before-sleep hot paths are relaxed loads. Only after one returns nonzero does the code acquire-load `migration.phase`; there is no acquire fallback when the outer load returns zero. Thus the release/acquire ordering described below applies to a path that enters the phase check, while the C-level protocol does not itself forbid a stale relaxed zero from skipping that check. ([src/server.c:4387-4395](../../../src/server.c#L4387-L4395), [src/server.c:4438-4448](../../../src/server.c#L4438-L4448), [src/server.c:8327-8336](../../../src/server.c#L8327-L8336), [src/server.c:15696-15698](../../../src/server.c#L15696-L15698), [src/server.c:15620](../../../src/server.c#L15620))

### 4. Execute the sentinel and acknowledge

The worker executes each popped batch in queue order. When a fake has an execution tail and a non-`NULL` `drain_ack`, the worker release-stores `1` to `fence_acked[i]`, frees the fake, advances the batch cursor, and produces no reply. ([src/server.c:22068-22105](../../../src/server.c#L22068-L22105)) The acknowledgement occurs in the execution loop, not merely when `exQueuePopBatch` advances `head`. ([src/server.c:21024-21053](../../../src/server.c#L21024-L21053), [src/server.c:22096-22105](../../../src/server.c#L22096-L22105))

After all jobs in any ordinary batch have executed, the worker release-stores that lane's post-pop `head` into `q->retired`. This separate execution frontier is what makes `retired == tail` a quiescence proof for a lane that has no live producer. Atomic owner-local publication is not a ring lane and is covered separately by atomic lifecycle references. (`src/server.c`)

### 5. Wait, wake, fall back for dead slots, or abort

For each `t < nprod`, the coordinator acquire-loads `fence_acked[t]` and skips an acknowledged slot. Otherwise it relaxed-loads `head`, acquire-loads `tail`, and acquire-loads `retired`; `head == tail && retired != tail` only increments the `reshard_fence_midbatch` diagnostic. ([src/server.c:15985-16000](../../../src/server.c#L15985-L16000))

If the producer is not live and `retired == tail`, the coordinator release-stores its acknowledgement and continues. If the producer is live, it wakes the slot only when `co_last_wake == 0` or `now - co_last_wake >= 500` microseconds; any unresolved slot sets `pending = 1`. ([src/server.c:15985-16010](../../../src/server.c#L15985-L16010)) Thus `head == tail` is never an acknowledgement predicate: only source-worker sentinel execution, or `retired == tail` combined with a non-live producer, completes a slot. ([src/server.c:15953-15984](../../../src/server.c#L15953-L15984), [src/server.c:15991-16009](../../../src/server.c#L15991-L16009))

While any slot is pending, a positive `reshard_fence_timeout_ms` aborts when `now - co_fence_t0 >= timeout_ms * 1000`. The abort relaxed-increments `reshard_fence_aborts`, sets `co_aborted = 1`, clears `tm_mig_flip_action`, release-stores `MIG_DONE`, increments `migration.gen` with release ordering, leaves the bucket table unchanged, sequence-consistently reopens `tomo_atomic_cutover_gate`, conditionally wakes atomic waiters, unconditionally calls `migWakeProducer(t2)` for every nonzero producer index `1 .. nprod - 1`, and release-stores `CO_WAIT_DONE`. The broadcast is by slot index; it is not conditional on liveness or parked-list membership. ([src/server.c:16011-16040](../../../src/server.c#L16011-L16040))

### 6. Flip only after all acknowledgements

When no slot remains pending, the coordinator release-stores `CO_WAIT_APPLIED`. On the subsequent state-machine arm it writes `ex_bucket_table[b] = dst` for every `b` in `[lo, hi)`, then updates exactly one boundary: `ex_bucket_end[src] = lo` when `dst == src + 1`, otherwise `ex_bucket_end[dst] = hi`. It release-stores `MIG_FLIPPED`, release-increments `migration.gen`, sequence-consistently reopens `tomo_atomic_cutover_gate`, and conditionally wakes atomic waiters. ([src/server.c:16042-16062](../../../src/server.c#L16042-L16062))

After publishing the flip, the coordinator wakes all nonzero producer slots. `migReleaseParkedClients` retains clients while an acquire-load still sees `MIG_DRAINING`; after a flip or abort it removes each client from the list, clears `CLIENT_PIPELINE_STALLED`, and re-enters `processInputBuffer`, which reroutes it under the current bucket table. ([src/server.c:15714-15736](../../../src/server.c#L15714-L15736), [src/server.c:16058-16070](../../../src/server.c#L16058-L16070))

### 7. Tear down after either flip or abort

On the successful path, `CO_WAIT_REFS` release-stores `MIG_DONE` and then release-stores `CO_WAIT_DONE`; either the atomic-lifecycle pre-drain abort or the producer-fence abort has already published those two states on its own path. In `CO_WAIT_DONE`, the coordinator acquire-checks `phase == MIG_DONE`, acquire-loads the destination worker's `loop_seq` into `co_hb0`, and release-stores `CO_QUIESCE`. ([src/server.c:15906-15928](../../../src/server.c#L15906-L15928), [src/server.c:16028-16040](../../../src/server.c#L16028-L16040), [src/server.c:16076-16094](../../../src/server.c#L16076-L16094))

`CO_QUIESCE` waits until an acquire-load of the destination heartbeat is at least `co_hb0 + 3`. It then captures and clears the pending flip action, release-stores `CO_IDLE`, and only afterward release-stores `migration_active = 0`; the active flag is explicitly the last publication. It relaxed-increments `reshard_done_seq` and may then publish a requested role change. ([src/server.c:16095-16139](../../../src/server.c#L16095-L16139))

Teardown does not store `MIG_IDLE`: `migration.phase` remains `MIG_DONE` after the active gate falls, until a later successful `reshardArm` release-stores `MIG_COPYING` for the next migration. ([src/server.c:15606-15620](../../../src/server.c#L15606-L15620), [src/server.c:16076-16119](../../../src/server.c#L16076-L16119))

## Enforced invariants

- One TLS generation value permits at most one successfully enqueued sentinel per live producer and cutover; it is updated only after the push completes. ([src/server.c:15630-15642](../../../src/server.c#L15630-L15642))
- The `drain_ack` pointer is a marker, not the acknowledgement address selected by the consumer; every sentinel stores `&fence_acked[0]`, while execution writes `fence_acked[i]` for its actual queue lane. ([src/server.c:15638-15640](../../../src/server.c#L15638-L15640), [src/server.c:22096-22102](../../../src/server.c#L22096-L22102))
- A live producer's acknowledgement proves that the source worker executed every entry that was already ahead of its sentinel in that producer's source ring. ([src/server.c:15634-15641](../../../src/server.c#L15634-L15641), [src/server.c:22096-22105](../../../src/server.c#L22096-L22105)) It does not prove retirement of a fake that was still in `tomo_stage` when the sentinel was published and was appended behind it later. ([src/server.c:3986-4018](../../../src/server.c#L3986-L4018), [src/server.c:4387-4412](../../../src/server.c#L4387-L4412))
- For a still-unacknowledged non-live slot, the coordinator accepts the fallback only when its execution frontier equals its published tail. A slot already acknowledged by sentinel execution is skipped before the liveness test. ([src/server.c:15990-16004](../../../src/server.c#L15990-L16004))
- Queue emptiness (`head == tail`) is diagnostic only because `head` advances before execution; neither that equality nor elapsed idle time authorizes a flip. ([src/server.c:15953-15984](../../../src/server.c#L15953-L15984), [src/server.c:15993-16003](../../../src/server.c#L15993-L16003))
- Failure to drain either the atomic-lifecycle pre-fence or the producer fence before a configured timeout aborts without changing ownership; neither timeout has a forced-flip branch. ([src/server.c:15894-15928](../../../src/server.c#L15894-L15928), [src/server.c:16011-16040](../../../src/server.c#L16011-L16040))
- Teardown waits for three destination-worker loop-heartbeat advances and publishes coordinator idle before clearing the one-migration-at-a-time active gate. ([src/server.c:16087-16119](../../../src/server.c#L16087-L16119))
