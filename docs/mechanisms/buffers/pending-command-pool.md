# `pendingCommand`, `pendingCommandList`, and `pendingCommandPool` — pending-command parse queue and recyclers

`pendingCommand` is the hand-off object between request parsing and command execution. A real client owns an intrusive `pendingCommandList`; completed entries are executable, while an incomplete tail can retain a partially parsed multibulk request across reads ([`src/server.h:1302-1310`](../../../src/server.h#L1302-L1310), [`src/networking.c:4473-4538`](../../../src/networking.c#L4473-L4538)). Two distinct recyclers retain these objects: a fixed, per-I/O-owner LIFO pool and the dynamically sized shared `pendingCommandPool` in `server.cmd_pool` ([`src/networking.c:4025-4044`](../../../src/networking.c#L4025-L4044), [`src/server.h:1310-1318`](../../../src/server.h#L1310-L1318), [`src/server.h:3511-3512`](../../../src/server.h#L3511-L3512)).

## Stored state

The exact `pendingCommand` field order is: `int argc`, `int argv_len`, `robj **argv`, `size_t argv_len_sum`, `unsigned long long input_bytes`, `struct redisCommand *cmd`, embedded `getKeysResult keys_result`, `long long reploff`, `int flags`, `int slot`, `uint8_t read_error`, `uint64_t argv_released_mask`, then intrusive `pendingCommand *next` and `*prev` ([`src/server.h:4230-4250`](../../../src/server.h#L4230-L4250)). Its flag word distinguishes incomplete parsing, preprocessing, valid key results, and heap-allocated key results; debug builds add four initialization-witness flags at bits 27 through 30 ([`src/server.h:4216-4228`](../../../src/server.h#L4216-L4228)).

`getKeysResult` is exactly two `int` fields (`numkeys`, `size`), six inline `keyReference { int pos; int flags; }` entries, and a `keyReference *keys`. That pointer is `NULL` in the initialized or not-yet-extracted state and, when populated, points to `keysbuf` or a heap allocation; `getKeysFreeResult()` frees only the heap case ([`src/server.h:4145-4164`](../../../src/server.h#L4145-L4164), [`src/server.h:5958-5967`](../../../src/server.h#L5958-L5967), [`src/server.c:7725-7734`](../../../src/server.c#L7725-L7734)). On LP64, `keyReference` is 8 bytes, `getKeysResult` is 64 bytes, and `pendingCommand` is 152 bytes; these are ABI-derived values, not `static_assert` contracts ([`src/server.h:4145-4164`](../../../src/server.h#L4145-L4164), [`src/server.h:4230-4250`](../../../src/server.h#L4230-L4250)). The source intends the inline key result to fit one cache line but does not cache-line-align it or the containing command; a 152-byte command is 2.375 64-byte-line equivalents or 1.1875 128-byte-line equivalents and can touch an additional line when its allocation is not line-aligned ([`src/config.h:38-44`](../../../src/config.h#L38-L44), [`src/server.h:4145-4164`](../../../src/server.h#L4145-L4164), [`src/server.h:4230-4250`](../../../src/server.h#L4230-L4250)).

The exact `pendingCommandList` layout is `pendingCommand *head`, `pendingCommand *tail`, `int len`, and `int ready_len`; its LP64 footprint is 24 bytes. The exact `pendingCommandPool` layout is `pendingCommand **pool`, `int size`, `int capacity`, and `int min_size`; it is also 24 bytes on LP64. Neither struct contains atomics or explicit alignment ([`src/server.h:1302-1318`](../../../src/server.h#L1302-L1318)). `ready_len` counts entries without `PENDING_CMD_FLAG_INCOMPLETE`; append and pop update both counters and clear both links on removal ([`src/networking.c:6767-6821`](../../../src/networking.c#L6767-L6821)).

## The two recyclers

|---|---|---|---|

On LP64 the pointer table is 132,096 bytes total. One saturated owner can retain at most `128 * (152 + 64 * 8) = 84,992` requested payload bytes, excluding allocator metadata and referenced `robj`s ([`src/server.h:4234-4250`](../../../src/server.h#L4234-L4250), [`src/networking.c:4025-4044`](../../../src/networking.c#L4025-L4044)). |
| Shared | `redisServer.cmd_pool`, initialized with a 16-pointer array; its controller tracks current `size`, allocated `capacity`, and the minimum observed size ([`src/server.h:3511-3512`](../../../src/server.h#L3511-L3512), [`src/server.c:6217-6220`](../../../src/server.c#L6217-L6220)). | Reclaim inserts only if both stock and custom I/O threading are inactive and `argv_len < 64`. On LP64 its maximum pointer array is 8,192 bytes, and its strict 63-pointer argument limit gives an upper bound of `1,024 * (152 + 63 * 8) + 8,192 = 679,936` requested retained bytes, excluding allocator metadata and `robj`s ([`src/server.h:4234-4250`](../../../src/server.h#L4234-L4250), [`src/networking.c:6657-6670`](../../../src/networking.c#L6657-L6670)). |

The local count object is explicitly aligned and padded to `CACHE_LINE_SIZE`, preventing two owners' counters from sharing a line ([`src/networking.c:445-458`](../../../src/networking.c#L445-L458)). That line is 128 bytes on Apple/AArch64 builds and 64 bytes otherwise unless supplied by the build, so the 129-counter table occupies 16,512 or 8,256 bytes respectively ([`src/config.h:38-44`](../../../src/config.h#L38-L44), [`src/networking.c:4036-4044`](../../../src/networking.c#L4036-L4044)). The pointer rows and retained command allocations have no equivalent cache-line alignment guarantee ([`src/networking.c:4025-4044`](../../../src/networking.c#L4025-L4044)).

## Allocation, reuse, and shrinking

Acquisition first pops the caller's local pool. If that is empty, it pops the shared pool and updates `min_size`; if both are empty, it allocates a command and performs a cold initialization ([`src/networking.c:6596-6631`](../../../src/networking.c#L6596-L6631)). Cold initialization zeroes the whole object and sets the slot invalid, whereas the hot reset changes only `argc`, `argv_len_sum`, flags, parse error, and released mask; capacity and the reusable `argv` allocation deliberately survive ([`src/networking.c:4002-4023`](../../../src/networking.c#L4002-L4023), [`src/networking.c:6719-6725`](../../../src/networking.c#L6719-L6725)). Lazy parser/preprocessor paths therefore must overwrite command, key, slot, offset, and link state before reading them again ([`src/networking.c:4002-4023`](../../../src/networking.c#L4002-L4023), [`src/server.c:7692-7746`](../../../src/server.c#L7692-L7746)).

Before recycling, cleanup decrements every unreleased argument, frees an allocated key-result array, and removes the retained argument bytes from client accounting ([`src/networking.c:6672-6717`](../../../src/networking.c#L6672-L6717)). A released bit covers positions below 64; worker cleanup nulls argument pointers at positions 64 and above instead ([`src/server.c:21651-21664`](../../../src/server.c#L21651-L21664)). If threaded execution still owns a command, reclaim may decrement only independently referenced objects and defer the command rather than race that ownership; otherwise it ultimately calls `freePendingCommand()` ([`src/networking.c:6686-6717`](../../../src/networking.c#L6686-L6717)).

Every two seconds `pendingCommandPoolCron()` returns if stock I/O threads are active; otherwise, when `capacity > 16`, it computes `utilization_ratio = 1.0 - min_size / capacity`, calls shrink only if that value is below 0.5, and finally resets `min_size = size` ([`src/server.c:2338-2354`](../../../src/server.c#L2338-L2354), [`src/server.c:2985-2988`](../../../src/server.c#L2985-L2988)). `shrinkPendingCommandPool()` itself returns when `capacity <= 16`; otherwise it computes `target_size = max(size / 2, 16)`, directly frees commands and argument arrays while `size > target_size`, then sets `capacity = target_size` and resizes the pointer array. Thus an existing `size < 16` stays below 16 while capacity becomes 16 ([`src/networking.c:6843-6866`](../../../src/networking.c#L6843-L6866)). Shared-pool insertion separately excludes both stock and custom I/O threads ([`src/networking.c:6657-6661`](../../../src/networking.c#L6657-L6661)).

## Parse-to-execution lifecycle

The request parser keeps at most the configured lookahead of parsed commands. Inline requests acquire a new command, while a multibulk request pops and resumes an incomplete tail; parsing appends the result and stops on an error or incomplete input ([`src/networking.c:4473-4557`](../../../src/networking.c#L4473-L4557)). When the initial multibulk count exceeds the retained vector, allocation replaces it with `min(multibulklen, 1024)` pointers; if parsing later fills that vector, growth sets `argv_len = min(argv_len < INT_MAX / 2 ? argv_len * 2 : INT_MAX, argc + multibulklen)` and reallocates ([`src/networking.c:4095-4105`](../../../src/networking.c#L4095-L4105), [`src/networking.c:4212-4220`](../../../src/networking.c#L4212-L4220)). Preprocessing resolves the command, validates arity, extracts keys and slot, and records whether the key result is inline or allocated ([`src/server.c:7692-7746`](../../../src/server.c#L7692-L7746)). The ready head is then copied into the real client's execution fields and becomes `current_pending_cmd` ([`src/networking.c:4558-4610`](../../../src/networking.c#L4558-L4610)).

Dispatch moves that current command and its client execution state to a fake client, removes the queue head, and clears the real client's current pointer ([`src/server.c:20714-20816`](../../../src/server.c#L20714-L20816)). Normal completion resets the client for its next command and eventually reclaims the command; direct reset/free paths instead pop and free queued entries, and MULTI owns queued pending-command pointers until transaction cleanup ([`src/networking.c:3638-3701`](../../../src/networking.c#L3638-L3701), [`src/networking.c:4280-4305`](../../../src/networking.c#L4280-L4305), [`src/multi.c:63-119`](../../../src/multi.c#L63-L119)).

Direct callers are code-path specific: `processInputBuffer()` calls `acquirePendingCommand()` and `addPendingCommand()`; `preprocessCommand()` fills the lazy command/key metadata; `moveExecutionStateSlim()` and `moveExecutionState()` pop the real head and append it to a dispatched fake; `commandProcessed()` reaches `reclaimPendingCommand()`/`freePendingCommand()` through reset/next-command processing; `queueMultiCommand()` and `freeClientMultiState()` transfer and release transaction-owned commands; AOF loading appends a synthetic pending command for MULTI; and `pendingCommandPoolCron()` invokes `shrinkPendingCommandPool()` ([`src/networking.c:4490-4577`](../../../src/networking.c#L4490-L4577), [`src/server.c:7692-7746`](../../../src/server.c#L7692-L7746), [`src/server.c:20714-20816`](../../../src/server.c#L20714-L20816), [`src/networking.c:3638-3701`](../../../src/networking.c#L3638-L3701), [`src/networking.c:4280-4305`](../../../src/networking.c#L4280-L4305), [`src/multi.c:63-119`](../../../src/multi.c#L63-L119), [`src/aof.c:1663-1677`](../../../src/aof.c#L1663-L1677), [`src/server.c:2338-2354`](../../../src/server.c#L2338-L2354)).

## Concurrency contract

Neither pool contains atomics: each local stack and its padded count belong to its I/O owner; shared-pool insertion requires both threaded-I/O modes to be inactive, and acquisition forbids a nonempty shared pool only when stock I/O threads are active ([`src/networking.c:4025-4044`](../../../src/networking.c#L4025-L4044), [`src/networking.c:6596-6617`](../../../src/networking.c#L6596-L6617), [`src/networking.c:6657-6669`](../../../src/networking.c#L6657-L6669)). For an ordinary worker-routed fake, ownership crosses threads through the [SPSC dispatch ring](spsc-dispatch-ring.md): the producer publishes queue state with release ordering and the worker observes it with acquire ordering ([`src/server.c:20852-20889`](../../../src/server.c#L20852-L20889), [`src/server.c:21024-21053`](../../../src/server.c#L21024-L21053)). That worker release-publishes the parent real client's [CDB completion byte](cdb-completion-slots.md) selected by the fake's `cdb` and `fake_slot`, and the I/O owner acquires it before consuming command state and reclaiming the object; cross-shard heads and synchronous fallback fakes use the alternate producers documented by the fake-client ring ([`src/server.c:3149-3168`](../../../src/server.c#L3149-L3168), [`src/server.c:8478-8482`](../../../src/server.c#L8478-L8482), [`src/server.c:8575-8640`](../../../src/server.c#L8575-L8640), [`src/server.c:22242-22252`](../../../src/server.c#L22242-L22252), [`src/server.c:4236-4241`](../../../src/server.c#L4236-L4241)).

The pending list, pool stacks, and command fields rely on that ownership transfer rather than per-field atomics. Recycling before the completion acquire, or sharing a local pool between owners, would violate this contract ([`src/server.c:3149-3168`](../../../src/server.c#L3149-L3168), [`src/networking.c:4025-4044`](../../../src/networking.c#L4025-L4044)). The dispatched command travels in a slot of the [fake-client ring](fake-client-ring.md); its output uses the [reply-buffer mechanism](reply-buffer.md), and completion can release [group pin slots](group-pin-slots.md) before reuse ([`src/server.c:8402-8475`](../../../src/server.c#L8402-L8475), [`src/server.c:4120-4383`](../../../src/server.c#L4120-L4383)). See the [thread-per-core execution model](../../execution-model.md) for the subsystem-level ownership flow.
