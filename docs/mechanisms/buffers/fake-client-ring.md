# `clientExecTail.fakeClients[]` — per-real-client fake-client pipeline ring

Each real client with an execution tail owns a fixed table of 32 fake-client pointers. Wrapping `unsigned int` dispatch and flush counters select a bounded active window in that table, allowing commands from one connection to execute concurrently while replies are committed in dispatch order ([`src/server.h:1839-1851`](../../../src/server.h#L1839-L1851), [`src/server.c:8314-8325`](../../../src/server.c#L8314-L8325), [`src/server.c:8402-8475`](../../../src/server.c#L8402-L8475)). Slots are materialized lazily, and a real client cannot be freed until the active window drains ([`src/server.c:8402-8450`](../../../src/server.c#L8402-L8450), [`src/networking.c:2708-2739`](../../../src/networking.c#L2708-L2739)).

## Layout and footprint

`clientExecTail` starts with `cdbSlots *reply_cdb`, the real client's completion-table pointer, followed by `client *fakeClients[TOMO_PIPELINE_DEPTH_MAX]` and, later, the ring counters and control state ([`src/server.h:1778-1851`](../../../src/server.h#L1778-L1851)). `TOMO_PIPELINE_DEPTH_MAX` is 32, so the pointer table is 256 bytes on LP64 and is embedded in the tail rather than separately allocated ([`src/server.h:1558-1559`](../../../src/server.h#L1558-L1559), [`src/server.h:1778-1787`](../../../src/server.h#L1778-L1787)). The table has no explicit cache-line alignment; the enclosing tail union is aligned only to `uint64_t`. Its 256 bytes equal four 64-byte-line payloads or two 128-byte-line payloads, but an unaligned placement can make it touch a fifth or third line respectively ([`src/config.h:38-44`](../../../src/config.h#L38-L44), [`src/server.h:1769-1873`](../../../src/server.h#L1769-L1873)).

The client execution core is statically asserted to 320 bytes. The tail is statically asserted to 840 bytes normally and 904 bytes with request/response logging, making a full client 1,160 or 1,224 bytes respectively ([`src/server.h:1769-1775`](../../../src/server.h#L1769-L1775), [`src/server.h:1875-1965`](../../../src/server.h#L1875-L1965)). Fake clients start as either a 320-byte core allocation or a full allocation; both additionally request a 1,024-byte reply buffer and allocate an empty list header, which is 48 bytes on LP64 ([`src/networking.c:339-419`](../../../src/networking.c#L339-L419), [`src/adlist.h:16-34`](../../../src/adlist.h#L16-L34), [`src/adlist.c:22-33`](../../../src/adlist.c#L22-L33)). Thus the minimum requested payload per materialized slot on LP64 is 1,392 bytes for a core fake, 2,232 bytes for a normal full fake, or 2,296 bytes for a logging full fake, before allocator metadata and reply-list nodes ([`src/server.h:1769-1775`](../../../src/server.h#L1769-L1775), [`src/networking.c:339-419`](../../../src/networking.c#L339-L419)).

A core fake is eligible exactly when `c->cmd != NULL`, `c->cmd->tomo_route & TOMO_R_EXPRESS`, and either `(proc == getCommand && argc == 2)` or `(proc == setCommand && argc == 3)`. A `LOG_REQ_RES` build disables it, as does any registered callback in `NOTIFY_KEY_MISS | NOTIFY_EXPIRED | NOTIFY_STRING | NOTIFY_NEW | NOTIFY_OVERWRITTEN | NOTIFY_TYPE_CHANGED` ([`src/server.c:8410-8422`](../../../src/server.c#L8410-L8422)). If a later command in that slot needs the full tail, promotion requires a quiescent fake, copies the 320-byte core, zeroes and initializes the new tail, preserves the slot number, and frees the core allocation; there is no demotion path ([`src/networking.c:422-442`](../../../src/networking.c#L422-L442)).

Each fake has its own reply list and reply buffer. For a plain append, growth runs exactly when `c->isFake && listLength(c->reply) == 0 && bufpos + len > buf_usable_size && buf_usable_size < FAKE_BUF_MAX_BYTES`; it sets `need = bufpos + len`, starts `ns` at the current usable size or `FAKE_BUF_START_BYTES`, doubles while `ns < need && ns < FAKE_BUF_MAX_BYTES`, clamps to 65,536, and preserves the used prefix. Data that still cannot fit spills to reply blocks ([`src/server.h:183-185`](../../../src/server.h#L183-L185), [`src/networking.c:339-419`](../../../src/networking.c#L339-L419), [`src/networking.c:965-988`](../../../src/networking.c#L965-L988)). See [reply buffers](reply-buffer.md) for that allocation and transfer path.

## Ring state and index formulas

The exact controlling fields are ordinary, non-atomic `unsigned int dispatchid`, `flushid`, `fake_ring_cur_depth`, `ring_size`, `ring_mask`, `ring_want_grow`, `cs_barrier`, `fake_ring_decay_skip`, and `fake_ring_hwm_win`, plus ordinary `double fake_ring_hwm_ewma` ([`src/server.h:1790-1792`](../../../src/server.h#L1790-L1792), [`src/server.h:1839-1851`](../../../src/server.h#L1839-L1851)). Their roles are:

| Quantity | Exact rule |
|---|---|
| In-flight count | Unsigned `dispatchid - flushid`; the ring is full exactly when this equals `ring_size` ([`src/server.c:8314-8325`](../../../src/server.c#L8314-L8325)). |
| Dispatch slot | `fakeClients[dispatchid & ring_mask]` before `dispatchid++` ([`src/server.c:8402-8450`](../../../src/server.c#L8402-L8450), [`src/server.c:8494-8645`](../../../src/server.c#L8494-L8645)). |
| Flush slot | `fakeClients[flushid & ring_mask]`; flushing stops at the first completion byte that is not ready ([`src/server.c:4120-4241`](../../../src/server.c#L4120-L4241)). |
| Growth | If growth was requested and the ring is empty, clear the request; before clearing it, double `ring_size` and set `ring_mask = ring_size - 1` only when `ring_size < server.pipeline_ring_depth` ([`src/server.c:8304-8312`](../../../src/server.c#L8304-L8312)). |
| Wake space | A stalled client can wake outside an atomic window when a barrier has drained completely, or otherwise when `dispatchid - flushid < ring_size` ([`src/server.c:4340-4383`](../../../src/server.c#L4340-L4383)). |

Configuration accepts immutable `tomokv-pipeline-depth` values from -1 through 32; -1 maps to 32, zero maps to 1, and a positive value is retained ([`src/config.c:3313-3318`](../../../src/config.c#L3313-L3318), [`src/server.c:5856-5865`](../../../src/server.c#L5856-L5865)). Initialization rounds upward to a power of two, but then clamps that result back to the configured depth, and derives the mask as `size - 1` ([`src/networking.c:647-690`](../../../src/networking.c#L647-L690)). Consequently, current code accepts a positive non-power-of-two depth yet still uses bitwise-AND slot selection; after an empty-ring growth it can also double without clamping to the configured depth ([`src/config.c:3313-3318`](../../../src/config.c#L3313-L3318), [`src/networking.c:647-690`](../../../src/networking.c#L647-L690), [`src/server.c:8304-8312`](../../../src/server.c#L8304-L8312)). The power-of-two formulas are therefore safe only when the effective `ring_size` is a power of two; this is a code-level caveat, not a guarantee supplied by configuration validation.

`fake_ring_cur_depth` is a high-water prefix extent, not an in-flight count: after lazy creation at `fslot`, dispatch performs the equivalent of `fake_ring_cur_depth = max(fake_ring_cur_depth, fslot + 1)`. It stamps `fake_slot` and enrolls the real client for completion processing when the first command enters the ring ([`src/server.c:8423-8475`](../../../src/server.c#L8423-L8475)).

## Dispatch, completion, and ordered flush

Before dispatch, stateful-command, barrier, atomic-window, and ring-capacity gates may keep execution on the real client or mark it stalled ([`src/server.c:8191-8400`](../../../src/server.c#L8191-L8400)). Dispatch moves the pending command, arguments, identity, accounting, and the required execution state from the real client to the selected fake; the slim and full variants differ only in how much client state they carry ([`src/server.c:20714-20816`](../../../src/server.c#L20714-L20816)). An ordinary worker-routed fake crosses the [SPSC dispatch ring](spsc-dispatch-ring.md); a cross-shard ring head is not itself dispatched because its sub-fakes execute on workers, and the fallback branch executes the ring fake synchronously on its I/O owner ([`src/server.c:8478-8482`](../../../src/server.c#L8478-L8482), [`src/server.c:8575-8640`](../../../src/server.c#L8575-L8640), [`src/server.c:20852-20889`](../../../src/server.c#L20852-L20889)).

The ordinary worker, the cross-shard completion path, or the synchronous inline branch writes the result and release-publishes the parent real client's [CDB completion byte](cdb-completion-slots.md) selected by `fake->cdb` and `fake->fake_slot`. The I/O owner acquire-loads that byte before consuming the fake, then relaxed-clears it after handling the result ([`src/server.c:3149-3168`](../../../src/server.c#L3149-L3168), [`src/server.c:8630-8640`](../../../src/server.c#L8630-L8640), [`src/server.c:10336-10403`](../../../src/server.c#L10336-L10403), [`src/server.c:22180-22199`](../../../src/server.c#L22180-L22199), [`src/server.c:22242-22252`](../../../src/server.c#L22242-L22252)). The ring counters and pointer table need no atomics because the I/O owner alone mutates them; for worker-routed fakes, the dispatch queue's release/acquire handoff and the CDB release/acquire handoff bracket worker access to fake state ([`src/server.c:20852-20889`](../../../src/server.c#L20852-L20889), [`src/server.c:21024-21053`](../../../src/server.c#L21024-L21053), [`src/server.c:3149-3168`](../../../src/server.c#L3149-L3168)).

Flush walks strictly from `flushid` toward `dispatchid` and stops at the first unready slot, so a later completion cannot overtake an earlier reply on the connection ([`src/server.c:4120-4241`](../../../src/server.c#L4120-L4241)). For each ready slot it performs ordinary reply transfer or cross-shard group reassembly, clears completion, releases command/group snapshots, processes the completed command, decrements accounting, and advances `flushid` ([`src/server.c:4236-4341`](../../../src/server.c#L4236-L4341)). This terminal processing makes objects from the [pending-command pools](pending-command-pool.md) reclaimable and releases an armed [group pin slot](group-pin-slots.md) ([`src/networking.c:3638-3701`](../../../src/networking.c#L3638-L3701), [`src/server.c:1202-1215`](../../../src/server.c#L1202-L1215), [`src/server.c:4320-4341`](../../../src/server.c#L4320-L4341)).

Freeing a real client is deferred while `flushid != dispatchid`. Once drained, teardown scans all 32 table entries and frees every materialized fake before freeing the real client's completion storage ([`src/networking.c:2708-2739`](../../../src/networking.c#L2708-L2739)).

## Adaptive shrink

The decay pass ignores fake and disconnected clients, combines the current in-flight count with the sampling-window high-water mark, and updates an EWMA as `0.3 * hwm + 0.7 * old` ([`src/server.c:16590-16614`](../../../src/server.c#L16590-L16614)). It computes `target = floor(1.25 * ewma) + 1`, clamps that target to `[1, ring_size]`, and enters shrink only when `inflight == 0 && target < fake_ring_cur_depth`; an unexpired skip counter postpones the actual shrink ([`src/server.c:16608-16618`](../../../src/server.c#L16608-L16618)). Shrink rounds the target up to a power of two, frees materialized fake clients above that prefix, lowers `fake_ring_cur_depth`, updates `ring_size` and `ring_mask` if smaller, and installs a two-pass delay before another shrink ([`src/server.c:16619-16632`](../../../src/server.c#L16619-L16632)). Dispatch and flush sequence numbers are not reset by this path; emptiness makes their unsigned difference zero, and subsequent addressing continues through the updated mask ([`src/server.c:16590-16637`](../../../src/server.c#L16590-L16637)).

The direct lifecycle callers are `createClient()`, which initializes the table and controller; `processCommand()`, which selects, lazily creates or promotes, and dispatches a slot; `handleWorkerReplies()`, which drains completed slots in order; `fakeRingClientCron()`, which decays idle materialized capacity; and `freeClient()`, which defers while the ring is active and ultimately frees every materialized fake ([`src/networking.c:503-520`](../../../src/networking.c#L503-L520), [`src/networking.c:629-690`](../../../src/networking.c#L629-L690), [`src/server.c:8191-8645`](../../../src/server.c#L8191-L8645), [`src/server.c:4120-4383`](../../../src/server.c#L4120-L4383), [`src/server.c:16590-16637`](../../../src/server.c#L16590-L16637), [`src/networking.c:2708-2739`](../../../src/networking.c#L2708-L2739)).

See the [thread-per-core execution model](../../execution-model.md) for the subsystem-level queue, worker, completion, and connection-ownership flow.
