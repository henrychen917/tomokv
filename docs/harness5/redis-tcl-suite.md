# Redis 7.4.10 Tcl suite against TomoKV

Source baseline `3700b51d7` (no production change in this lane); TomoKV executable `ef368a64f969aa5b…` (`build/tomokv`, binary-neutral IDENTICAL to `bench-bins/tomokv-headline-3700b51d7`); oracle Redis 7.4.10 `ac08d444fabe9607…`. External-server mode: `./runtest --host 127.0.0.1 --port P --singledb --single FILE --clients 1`, one fresh server per file, 16 databases, TomoKV 16 shards, 2s at ratio 6:2 on eight CPUs. All runs were confined to CPUs 32–47 and ports 45800–45899.

The tree has 206 `.tcl` files: 135 executable unit/integration files (all attempted, including `unit/moduleapi`) and 71 support files and the separate cluster harness (listed in the summary).

Seven files never completed on TomoKV in the full-file run: `unit/introspection`, `unit/pause`, `unit/pubsub`, `unit/tracking`, `unit/type/list`, `unit/type/stream`, `unit/type/stream-cgroups`. Six stopped at a test that waited forever for a reply (60 s idle deadline); `unit/type/stream` stopped at a file-level `CONFIG SET appendonly yes` (immutable on TomoKV). Those files were rerun with every hung test named in `--skipfile` (and `--tags -needs:debug` for `unit/type/stream`, which removes only its appendonly blocks); the final pass used the same skip list for 2s, 1s and Redis, and Redis passes every assertion of it except one state-dependent `unit/type/list` test. Rows 4–6 replace those files by the reached run. Counts are assertion events, not independent defects; external mode skips the tests that need to own the server process.

A cascade is a test that fails only because an earlier test left state behind; it carries its root test's class and names it. Hangs count as failures.

## REAL compatibility defects (72 root causes)

One row per root cause. Each has a minimal reproduction in [redis-tcl-repros.json](redis-tcl-repros.json) (cases in [redis-tcl-repro-cases.json](redis-tcl-repro-cases.json)), replayed on fresh TomoKV 2s, TomoKV 1s and Redis 7.4.10 servers by `docs/harness5/repro_tcl.py`; the verdict compares the typed RESP replies. “Design note” marks deliberate TomoKV restrictions outside the owner’s unsupported-by-design list; they are still client-visible differences and are listed for the maintainer, not judged here.

**Read first.** `FUNCTION-LIST-CRLF` lets a client forge a reply on its own connection: the error reply echoes an argument's raw CR/LF, so the next command reads the injected `+INJECTED`. Upstream tests hang to the idle deadline (an expected reply, push, block or wake never arrives) under: `BLOCK-MOVE-WRONGTYPE-STRANDS`, `BLOCK-STREAM-REMOVED-NO-UNBLOCK`, `BLOCK-WAKE-RENAME-SORTSTORE`, `MONITOR-SCRIPT-CMDS`, `PAUSE-EXEC-NOT-HELD`, `PAUSE-MAY-REPLICATE`, `PAUSE-SCRIPT-FLAGS`, `PUBSUB-EVICT-ON-MAXMEMORY`, `PUBSUB-REPLY-OFF-PUSH`, `TRACK-BCAST-BATCH`, `TRACK-MAXKEYS-IMMUTABLE`; the BLOCK-* ones leave a blocked client unserved. Wrong data or ordering effects: `STREAM-TRIM-APPROX-LIMIT`, `BLOCK-CHAIN-ASYNC`, `BLOCK-WAKE-ORDER-MULTI`, `SCRIPT-NUMBER-ARG`, `RESTORE-IDLETIME-FREQ-IGNORED`, `DUMP-STREAM-REFUSED`. Out-of-memory gating gaps: `MULTI-OOM-QUEUE`, `MULTI-OOM-EXEC`, `PUBSUB-SUBSCRIBE-NO-DENYOOM`, `FUNCTION-LOAD-DENYOOM`, `PUBSUB-EVICT-ON-MAXMEMORY`. The remaining roots are error texts, introspection fields, configuration surface and the deliberate restrictions marked in the last column.
